Let's discuss algorithms that generate mazes. I'll focus on the conceptual mechanics, properties,
and trade-offs of the most common approaches, assuming a rectangular grid of cells (each with four
potential walls) unless noted.

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

1. Recursive Backtracker (Depth‑First Search based)
- How it works: Start at a random cell, mark it visited. While there are unvisited
neighbours, choose one uniformly at random, remove the wall between them, recurse on that
neighbour. If stuck (no unvisited neighbours), backtrack to the previous cell.
- Result: Produces a “perfect” maze (exactly one path between any two cells) with long,
winding corridors and few dead ends near the start. The branching factor is low.
- Pros: Simple, fast (O(n) time, O(n) stack space worst‑case). Very popular in hobby
projects.
- Cons: Recursive depth may overflow for huge mazes; iterative stack fixes that. Tends to
create mazes with a strong bias toward deep, twisty passages (some call it a “river” pattern).

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

2. Randomised Kruskal’s Algorithm
- How it works: List every internal wall (edge) between adjacent cells. Shuffle the list.
Process each wall: if the two cells are in different sets (checked via Union‑Find), remove the wall
and merge the sets.
- Result: Also a perfect maze. Tends to produce shorter, more “balanced” dead ends compared
to backtracker. The global randomness yields more uniform distribution of passages.
- Pros: Easy to parallelise (edge processing order independent). Produces no bias toward
long corridors.
- Cons: Requires O(N log N) time due to sorting; in practice shuffling is done which is
O(N). Need union‑find data structure.

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

3. Randomised Prim’s Algorithm
- How it works: Start with a single cell marked “in the maze”. Maintain a list of frontier
walls (edges from in‑maze to out‑of‑maze). Randomly pick a frontier wall, add the out‑maze cell to
the maze (remove the wall), then add its own frontier walls to the list. Continue until all cells
are in.
- Result: Again a perfect maze. Tends to grow in a more “tree‑like” shape with many short
dead ends (like Kruskal, but with a local expansion bias). The frontier list can be implemented as
a random‑selection structure.
- Pros: Avoids recursion depth issues. Simpler than Kruskal’s union‑find. Time O(N log N)
with a naive priority queue, but O(N) with a set and random removal.
- Cons: Still requires maintaining a frontier set. Produces mazes with slightly more
branching than backtracker.

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

4. Aldous‑Broder Algorithm
- How it works: Perform a uniform random walk on the grid. The first time you visit a cell,
break the wall from the previous cell. Continue until all cells are visited.
- Simplest to describe and implement.
- Result: Perfect maze, but much slower than others: the cover time for a random
walk on an N‑cell graph is O(N log N) in expectation, but the worst‑case can be much larger (e.g.,
hitting the last cell may take a huge detour). Very inefficient for large grids.
- Pros: No recursion, no data structures beyond visited flags. Mathematically elegant.
Works on any graph.
- Cons: Impractically slow for large mazes (e.g., 100x100). Rarely used in production.

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

5. Wilson’s Algorithm
- How it works: Start with one cell visited. Pick a random unvisited cell, then perform a
loop‑erased random walk: mark the walk until it hits a visited cell, then carve the path (removing
walls) and erase any loops encountered. Repeat until all cells visited.
- Result: Perfect maze, but the distribution is uniform over all spanning trees – which is
the same as Aldous‑Broder’s distribution. However, Wilson’s is much faster because it uses
loop‑erasure to avoid long revisits.
- Pros: Uniform spanning tree distribution (no bias). Fast in practice (expected O(N) for
grids, though hidden constants are high).
- Cons: More complex to implement (loop erasure). Still slower than backtracker or Kruskal
for typical sizes.

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

6. Eller’s Algorithm
- How it works: Build the maze row by row. For each row, maintain a set of “connected
components”. Decide which vertical walls to remove within the row (joining cells into the same
set), then decide which horizontal connections to make to the row below (joining sets across rows).
At the end close the last row properly.
- Result: Perfect maze. Very memory efficient – only needs to store the current row’s set
information, not the entire grid. Works well for very large or infinite mazes.
- Pros: O(N) time, O(width) memory. Real‑time generation with scrolling possible.
- Cons: Slightly more intricate logic for set merging and ensuring no loops. Not as widely
known.

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

7. Binary Tree & Sidewinder
- Binary Tree: For each cell, carve a passage either north or east (choose randomly).
Simple, but only works on rectangular grids and produces a strong bias: the top‑left cell is inside
a huge dead‑end, and the maze has a diagonal pattern.
- Sidewinder: Similar row‑by‑row algorithm: for each row, choose a random “run” of cells,
carve east within the run, then carve north from one cell in the run. Eliminates the top‑left bias
but still has a bias toward the bottom‑right corridors.
- Both: Very fast (O(N)), trivial to implement, but not perfect in the sense of
uniform distribution – they are biased and often used only for simple games or demos. They always
have a clear “escape” path along one wall.

8. Modifications & Variants
- Adding loops: Most algorithms produce perfect mazes (trees). To add loops, after
generation remove a small fraction of walls randomly.
- Hexagonal / triangular grids: All algorithms generalise to any planar graph; the same
logic applies (edges become walls).
- Grids with weights: For Prim’s or Kruskal’s, you can assign weights to walls (e.g.,
difficulty of carving) and use a priority queue to generate mazes with texture (e.g., rock/water
areas).
- Cellular automata & growing tree: The “Growing Tree” algorithm is a variant where you
maintain a list of active cells and choose a heuristic for which one to expand (backtracker is the
“last‑in‑first‑out” case; Prim’s is “random”). This lets you tune between long corridors and many
branches.

If you need a maze for a game, Recursive Backtracker or Kruskal are the most common
choices. For very large or infinite mazes, Eller shines. For academic interest in uniform
distributions, Wilson is preferred over Aldous‑Broder. The biased algorithms are only
suitable when speed is paramount and maze quality is secondary.
